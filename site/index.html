01 / Why Xencode

An agent that works on your terms

Not a chat wrapper. A real tool loop over your files, your tests and your model — with the guardrails you'd actually want.

⌁

Local-first, by default

Runs on Ollama, llama.cpp, llamacpp and free remote GPUs. Cloud models only when you explicitly opt in — and the status bar always tells you which rule is running.

◈

Real edit protocol

Whitespace-tolerant matching, structural AST edits, reference checks before a rename, and a continuation nudge when a small model stops after just reading.

⛨

Approval-gated tools

Every write and shell call stops at a modal showing the exact diff or command. Files are re-checked before approval is spent, so a moved file never gets a blind edit.

⟳

Proof over vibes

A 10-case seeded eval grades real cargo tests and file diffs. Retry and deep-think escalation are recorded in traces — no invented tool calls, no fake green.

⬡

Hybrid model stack

A fast Qwen-class default, BitNet as the weak-hardware fallback, a configured stronger model for deep thinking — all through one tool protocol.

◎

Development OS

Worktrees, background agents, orchestrator rail, skills, plugins, MCP + ACP, a floating badge, git loops and a full TUI — in one binary.

02 / How it works

From prompt to verified patch

Each step is a real operation with a real result. Nothing is simulated.

  1. 1

    Understand

    A shape classifier and hybrid lexical/symbol retrieval pick the files that matter, with a byte-stable prompt head.

  2. 2

    Act

    The model calls real tools — read, search, edit, run tests. Off-task tools can be hidden on bugfix turns to focus small models.

  3. 3

    Verify

    Grader tests run for real and findings are labelled introduced or pre-existing against the actual diff.

  4. 4

    Recover

    Failed edits are counted; at a turn boundary Xencode can hand the task to a stronger configured model — never mid-turn.

03 / Hybrid stack

The right brain for each job

Combine specialised models instead of betting on one. Weights are never merged; roles share the tool protocol.

04 / No GPU? No problem.

Borrow a free GPU

Colab brings a T4 through an SSH tunnel to 127.0.0.1:18000 — no public URL, no open port. Drive-backed caching makes repeat runs fast. Kaggle connection profiles are supported for private dial-out setups.

Live Colab/Kaggle runs depend on your Google account and runtime. The plumbing here is real and locally verified; the live session is yours to confirm.
no local GPUbash
# recommend a model from detected memory
xencode models advice

# preview the remote route — no VM touched
xencode setup --remote --dry-run

# bring up Colab + tunnel
xencode colab up --model qwen3-4b --quant Q4_K_M

# one-shot verify, then chat normally
xencode query "explain this repo"
xencode tui
