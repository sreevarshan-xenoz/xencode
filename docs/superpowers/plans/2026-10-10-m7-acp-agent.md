# `xencode acp` (M-7) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `xencode acp` lets Zed (and any ACP client) use xencode as its agent, as one more window onto the project's engine.

**Architecture:** A new crate `xencode-acp-rs` holds an ACP agent built on the official `agent-client-protocol` crate. Each ACP session connects to (or starts) the engine for its folder through `xencode_tui_rs::engine::link`, sends it `ClientMsg`s, and turns what the engine sends (`EngineMsg`s and view changes) into ACP `session/update`s. A pure translator (`turn.rs`) does the conversion so it can be tested with real engine messages and no I/O; the session code (`session.rs`) does the I/O.

**Tech Stack:** Rust 2021 workspace (crate itself may be 2021), tokio, `agent-client-protocol = "=3.3.0"` with the `stdio` feature (tests also use `process`), serde_json.

**Spec:** `docs/superpowers/specs/2026-10-10-acp-agent-design.md`

## Global Constraints

- Rust only; no Python; no mocks in product code or tests (`AGENTS.md`). Tests use the real `xencode` binary, the real engine, and either an address nobody listens on (`http://127.0.0.1:9`) or a real llama.cpp server named by `XENCODE_LIVE_LLAMACPP_URL` (tests needing it are `#[ignore]` with that reason).
- Pin `agent-client-protocol = { version = "=3.3.0", features = ["stdio"] }`. Protocol version answered: `1` (`ProtocolVersion::V1`).
- Standard output of `xencode acp` carries only ACP messages; all logs go to standard error.
- Every `cargo test` run sets `XCODE_CONFIG_DIR` to a fresh temp folder and uses `timeout -k`; on the laptop pass `-j 4`. Test the changed crate while iterating; `cargo test --workspace` before each commit; `cargo fmt --check` and `cargo clippy --workspace --all-targets -- -D warnings -A clippy::format-in-format-args` clean.
- One commit per stage, subject naming its ID (`M-7a` … `M-7e`), plain-English message ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never push.
- Tool kinds: `read_file`, `list_dir`, `read_docs` → `read`; `write_file`, `edit_file`, `edit_symbol`, `ast_edit` → `edit`; `search_files`, `find_refs`, `web_search` → `search`; `run_command`, `background_start` → `execute`; `web_fetch` → `fetch`; every other tool → `other`.
- Placeholders for credentials in tests follow the secret rule (`sk-FAKE-NOT-A-REAL-TEST-KEY` style).

## Review Focus

1. **A prompt arrives while the session's previous turn is still running** (Zed allows a second message). Expected: the second prompt is refused with a JSON-RPC error in words ("a turn is already running in this session"), the first goes on. Pinned in Task 3.
2. **The engine is lost mid-turn** (killed, crashed). Expected: the running prompt ends with a JSON-RPC error saying the engine was lost, not a hang; the next prompt reconnects or starts a new engine. Pinned in Task 3.
3. **`session/new` with a `cwd` that does not exist or is a file.** Expected: an error naming the folder, no engine started. Pinned in Task 3.
4. **A cancel while a permission request is open.** Expected: the open request is dropped, the engine is told `Stop`, the prompt answers `cancelled`. Pinned in Task 4.
5. **An edit to a file that is not UTF-8 or is very large.** Expected: the tool call is reported without a diff (no panic, no multi-megabyte message); a diff is sent only for UTF-8 files up to 512 KiB on both sides. Pinned in Task 4.

The ACP crate's API, checked in its 3.3.0 source: agents are `Agent.builder().name(..).on_receive_request(async move |req: T, responder, connection| {..}, agent_client_protocol::on_receive_request!())…connect_to(Stdio::new()).await`; notifications are `.on_receive_notification(async move |n: T, connection| {..}, agent_client_protocol::on_receive_notification!())`. Long work goes in `connection.spawn(async move { …; responder.respond(…) })` so the dispatch loop is not blocked. A request from the agent to the client is `connection.send_request(req).block_task().await` (only inside spawned work). Clients are `agent_client_protocol::Client.builder()…connect_with(AcpAgent::new(AcpAgentConfig::new(exe).arg("acp").env(k, v)), async move |connection: ConnectionTo<Agent>| {..})` (feature `process`). Schema types live in `agent_client_protocol::schema::v1`; their builder methods are listed in `agent-client-protocol-schema-1.11.0/src/v1/{agent,client,tool_call,plan}.rs` — when a constructor's argument list in this plan does not compile, read it there and keep the meaning.

```rust
//! `xencode acp` (M-7): xencode as an agent for editors that speak the Agent
//! Client Protocol, such as Zed. Each session is a window onto its folder's
//! engine (EN-2); standard output carries only protocol messages.

pub mod kinds;
pub mod session;
pub mod turn;

use agent_client_protocol::schema::v1::{
    AgentCapabilities, AuthMethod, AuthMethodAgent, AuthenticateRequest, AuthenticateResponse,
    Implementation, InitializeRequest, InitializeResponse, PromptCapabilities,
};
use agent_client_protocol::{Agent, Stdio};

pub const AUTH_METHOD_ID: &str = "xencode-settings";

pub async fn serve_stdio() -> Result<(), String> {
    let sessions = session::Sessions::default();
    Agent.builder().name("xencode")
        .on_receive_request(async move |init: InitializeRequest, responder, _c| {
            responder.respond(
                InitializeResponse::new(init.protocol_version.min(agent_client_protocol::schema::ProtocolVersion::V1))
                    .agent_info(Implementation::new("xencode", env!("CARGO_PKG_VERSION")))
                    .agent_capabilities(AgentCapabilities::new().prompt_capabilities(
                        PromptCapabilities::new().image(true).embedded_context(true)))
                    .auth_methods(vec![AuthMethod::Agent(AuthMethodAgent::new(
                        AUTH_METHOD_ID, "Use xencode's settings"))]),
            )
        }, agent_client_protocol::on_receive_request!())
        .on_receive_request(async move |_auth: AuthenticateRequest, responder, _c| {
            match xencode_config_rs::XencodeConfig::load() {
                Ok(c) if !c.default_model.trim().is_empty() => responder.respond(AuthenticateResponse::new()),
                _ => responder.respond_with_error(agent_client_protocol::Error::invalid_request().data(
                    "no model is set: run `xencode setup` or `xencode config set default_model <model>`")),
            }
        }, agent_client_protocol::on_receive_request!())
        // session handlers are added in Task 3 through `sessions`
        .connect_to(Stdio::new())
        .await
        .map_err(|e| e.to_string())
}
```

```rust
pub fn feed(&mut self, msg: &EngineMsg) -> Vec<Out> {
    match msg {
        EngineMsg::Event { token } => self.token(token),
        EngineMsg::ApprovalRequested { approval } => vec![Out::Permission(approval.clone())],
        EngineMsg::QuestionAsked { id, text } => vec![Out::Question(*id, text.clone())],
        EngineMsg::Error { message } => vec![Out::Ended(Ending::Failed(message.clone()))],
        _ => Vec::new(),
    }
}

fn token(&mut self, token: &str) -> Vec<Out> {
    if token == "[DONE]" {
        return vec![Out::Ended(if self.stopped { Ending::Stopped } else { Ending::Done })];
    }
    if token == "[STOPPED]" { self.stopped = true; return Vec::new(); }
    // Tool tokens: Task 4. Every other `[TAG]…` line is for the terminal.
    if token.starts_with('[') && token[1..].find(']').is_some_and(|i| token[1..=i].chars().all(|c| c.is_ascii_uppercase() || c == '_')) {
        return Vec::new();
    }
    vec![Out::Text(token.to_string())]
}
```
